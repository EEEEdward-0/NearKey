# NearKey / 近钥（Windows）

Windows 11 上的本机应用。后台支持开机自动启动的原生 C++ Windows 服务，登录后另有会话后台执行自动锁定；设置界面是单独的 WPF 进程，关闭窗口后驻留托盘。登录组件沿用 `demo/credential-provider`，保留 Windows 原有 PIN 和密码登录入口。

## 已实现

- 扫描附近 BLE 广播，在设置界面选择最多 8 台设备。
- 后台读取 Windows 已配对的 BLE 设备名称和地址；界面优先显示已选择、已配对设备，并标明是否真的收到最近 30 秒的广播。配对记录只用于识别，不单独满足解锁条件。
- 只对最近 20 秒内检测到的已选设备计算 RSSI 均值；只检测到其中一台时按这一台计算。
- 设置解锁阈值、锁定阈值、离开持续时间、键盘解锁键（Enter 或 A–Z），以及自动解锁和自动锁定开关。锁定阈值应低于解锁阈值，减少信号在边界波动时的反复操作。
- 解锁可选 A「仅蓝牙」、B「局域网设备在线」、C「蓝牙与局域网同时满足」。局域网支持配置一至两台设备；一台时该设备在线即通过，两台时必须两台都在线。局域网用各设备 IPv4 和 Wi-Fi MAC 匹配本地链路上的 ARP 应答；自动锁定仍使用原有蓝牙规则。
- 局域网信息支持自动补全：填写 IP 后读取对应 MAC，或用已有 Wi-Fi MAC 查找当前 IP。邻居表没有匹配记录时，会在正在使用的以太网／Wi-Fi 子网中并发发起 ARP 探测；支持 /22 至 /30 子网，20 秒后停止发起新探测，已发出的请求等待系统返回。结果需 ARP 应答确认，填入后由用户检查并保存。蓝牙配对记录无法直接推导手机的 Wi-Fi 地址。
- 后台通过本机命名管道向 Windows 登录组件提供状态；进入绑定账户的首次登录或锁屏第二层后，可在 PIN 界面按设置的键（默认 Enter，可改为单个英文字母）或点击解锁磁贴的 Login。靠近条件满足时才提交已配置的本机密码，原有 PIN／密码入口保留。
- 靠近条件不满足时，解锁磁贴拒绝提交并提示使用 Windows PIN 或密码；原生 PIN／密码入口始终保留。
- 手动锁定、登录后启动后台、状态查看和事件记录。事件日志达到 1 MB 后轮换到 `events.previous.log`。
- 试运行：输入假设的蓝牙信号与局域网在线台数，复用后台规则计算并说明解锁条件与自动锁定倒计时；预演不执行锁屏或解锁。
- 设置界面分为设备、解锁设置和运行记录三个独立页面。设备添加与移除立即保存，规则需点击保存设置；界面提供首次使用和锁屏测试步骤。关闭或最小化窗口后可从系统托盘重新打开、立即锁定或明确退出设置界面；后台继续运行。安装后登录 Windows 只自动启动托盘入口，不弹出设置窗口。
- 后台 BLE 广播通过事件接收，每 2 秒汇总规则、每 4 秒写一次界面快照；界面每 4 秒读取一次。设备列表只显示最近 30 秒收到的广播，明确区分已选择设备与身份未确认设备，并按冒号分组显示 MAC。
- 已配对设备列表每 60 秒从 Windows 更新一次；即使暂时没有广播，也在设备列表中标为“未检测到”，不会被算作靠近。

## 当前本机验收状态

- 已验证：后台停止、没有接近信号时，用户在真实锁屏界面可直接使用 Windows 原有 PIN／密码登录，不再被应用磁贴的报错困住。
- 已验证：B 模式下刻意把蓝牙阈值调到无法满足，局域网条件独立满足；用户在真实锁屏界面确认无点击自动进入桌面。C 模式在蓝牙不满足时拒绝，在两项都满足时通过后台判断；C 尚未单独做锁屏验收。测试后已恢复 A 模式及原阈值。
- 已验证：当前安装版在真实 PIN 登录层可检测到回车；用户反馈，iPhone 靠近时在该层按回车可进入桌面。长期稳定性及不同无线环境下的表现仍待观察。
- 已验证：普通用户和 SYSTEM 身份的登录组件探针曾取得接近状态；多设备均值、仅一台被检测到、信号过期及 A/B/C 条件组合通过算法测试。安装版界面已打开检查。
- 尚未实测：iPhone 移远后的自动锁定和界面“立即锁定”按钮。运行中的自动锁定开关以设置界面为准；此次改动不自行更改其原有开关。
- 尚未验收：Apple Watch 的独立身份识别，以及长时间运行、手机锁屏和不同无线环境下的稳定性。
- Apple Watch 移远对照：iPhone 留在电脑旁，分别采集手表近距离约 24 秒、移远约 60 秒、返回约 36 秒的广播。扫描结果中多条匿名地址持续存在，返回后也出现新地址；这次对照未找到可唯一且稳定归属手表的蓝牙地址。因此当前不能将 Apple Watch 标为已支持的独立解锁设备。
- 用户随后提供了 Apple Watch“关于本机”页面的蓝牙地址；当前 BLE 扫描列表及连续约 30 秒复查均未出现该地址。设备页面上的蓝牙地址不能直接推定为 Windows 接收到的 BLE 广播地址。未验证地址可被扫描器持续观察到之前，不把它写入选中设备配置。

## 本机构建与安装

1. 安装 Visual Studio 2022 C++ Build Tools、Windows SDK 10.0.26100.0 和 .NET 10 SDK；运行 `app/build.ps1`。
   Windows ARM64 另需安装 Visual Studio 的 ARM64 C++ 工具组件，再运行 `app/build-arm64.ps1`。此脚本编译 ARM64 后台、登录组件和密码配置程序，并发布 `win-arm64` 设置界面。交叉编译已在当前电脑完成；仍需在 Windows ARM64 实机验收。
2. 首次安装前，按 `windows/README.md` 在本机交互窗口配置 Windows 登录密码。不要把密码放在聊天、命令行或项目文件中。
3. 以管理员身份运行 `app/install-app.ps1`。它会安装登录组件和应用文件，并创建开始菜单“蓝牙靠近解锁”快捷方式。
4. 打开“蓝牙靠近解锁”，选择设备、调整规则并保存。安装服务后，配置写到 `%PROGRAMDATA%\BluetoothUnlock\<账户 SID>\settings.ini`；首次安装从原 `%LOCALAPPDATA%\BluetoothUnlock` 迁移，后续更新保留已保存的服务配置。

在“键盘解锁键”中输入 Enter 或单个英文字母并保存后，进入 PIN 登录层按该键即可尝试靠近解锁；英文字母不区分大小写，留空时默认 Enter。此选项需要同时更新后台、登录组件和设置界面，首次使用需运行完整的 `app/install-app.ps1` 安装。

仅更新界面时，先发布 `app/frontend/BluetoothUnlock.UI.csproj` 到 `app/frontend/bin/publish`，再以管理员身份运行 `app/install-ui.ps1`，无需重装后台和登录组件。

界面使用已安装的 .NET 10 Desktop Runtime，不把运行时打包进应用。停止或移除应用时，以管理员身份运行 `app/uninstall-app.ps1`；设置和事件记录会留在用户目录及 ProgramData，便于用户自行决定是否删除。

### Windows 版本兼容范围

- 本项目当前以 Windows 11 x64 和 ARM64 为目标。.NET 官方的 [.NET 10 Windows 支持表](https://learn.microsoft.com/en-us/dotnet/core/install/windows) 列出 Windows 11 的 x64/ARM64，以及 Windows 10 的 LTSC/Enterprise 版本；普通 Windows 10 Home/Pro 不在该表的 .NET 10 支持范围内。安装设置界面需要 **.NET 10 Desktop Runtime**，只有基础 .NET Runtime 不够。
- 微软的 [Windows 凭据提供程序说明](https://learn.microsoft.com/en-us/windows/win32/secauthn/credential-providers-in-windows) 指出 Windows 支持 V1、V2 凭据提供程序，并建议始终保留至少一种系统自带登录方式。本项目保留 Windows PIN／密码入口；不同大版本的真实登录界面仍须在对应系统上验收，不能只凭编译成功认定兼容。
- 安装时的密码配置窗口使用 `_getwch` 安全读取；按照[微软文档](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/getch-getwch?view=msvc-170)，该函数不会回显输入。新版会以 `*` 表示收到按键，按 Enter 后进入确认输入；两次不一致不会保存。请填写账户密码，不是 PIN。

## 设备判断说明

- 已在这台电脑上验证 iPhone 的固定广播地址。某些设备（包括 Apple Watch）可能使用变化的私有地址；界面会显示匿名广播，但仅凭 Apple 厂商字段不能可靠确认哪条属于用户手表。移远对照仍未找出可稳定归属手表的地址，不应把匿名条目标成已验证的 Apple Watch。
- 蓝牙地址和 RSSI 可以伪造；它们不是强身份认证。启用自动解锁时，保存在本机受限注册表中的密码会由登录组件提交。离开后仍存在广播间隔和短暂信号保留时间。
- 局域网 IP/MAC 和 ARP 应答同样可以伪造。B 模式只说明设备在同一局域网，不能判断它是否靠近电脑；iPhone 休眠、切换网络、DHCP 地址变动或私人 Wi-Fi 地址变化都可能使 B/C 暂时失效。局域网配置只保存在当前用户目录，不写入项目源码。
- 服务绑定本机密码配置中的一个 Windows 账户。首次登录和后续锁屏均要求当前设备条件满足，并按确认键或点击 Login；未绑定账户继续使用 Windows 原有方式。BitLocker 开机 PIN 属于 Windows 启动前阶段，不在此应用范围内。

双设备局域网配置需完整更新后台和界面：以管理员身份运行 `app/install-app.ps1`。第二台信息可单独自动补全，留空表示只配置一台；重复 IP 或 MAC 不能保存。

保存规则前会验证配置的 IP/MAC，IP 不匹配时按 Wi-Fi MAC 查找并提示确认修正；无法验证则不保存。首次只填 IP 补全时需核对 MAC 确认设备身份。运行时若原 IP 不再匹配，设备保持离线，后台至多每 60 秒发起一次按 MAC 查找；找到后重新探测，所有设备验证在线才通过。找回的 IP 仅用于当前后台运行，不覆盖用户保存的配置；运行记录会提示找回。

配置采用带版本号的 INI（当前 Version=2），旧无版本单台/双台配置在下次保存时迁移。保存先写同目录临时文件并刷新到磁盘，再整体替换 settings.ini；失败保留原文件。高于支持范围的配置禁止保存并停用自动解锁。运行状态单独写入 status.txt，包括各设备当前 IP、在线状态和本次后台启动以来最近在线时间；鼠标停留在界面局域网状态上可查看，不作为下次启动的在线依据。

## 开机服务与原有功能

- `BluetoothUnlockService` 以 LocalSystem 身份自动启动（`--service`），登录前即可监听 BLE 和验证局域网。蓝牙启动未就绪时重试，未检测到有效信号不会通过蓝牙条件。
- 登录组件使用绑定账户的 SID 查找服务管道，验证服务进程的 SYSTEM 身份及受保护的安装路径。首次登录仅在管理员安装并启用服务后开放，必须新按一次配置按键或点击 Login；选择磁贴、保持按键不算确认。
- `BluetoothUnlockSession` 登录任务以绑定用户的普通权限运行 `--session`，根据服务的新鲜快照执行原有蓝牙离开自动锁定；手动锁定仍在用户会话中执行。用户界面关闭后服务和会话任务继续运行。
- 手动 IP/MAC、单项补全、保存前校验、运行时 IP 恢复、多设备蓝牙平均值、两台局域网必须全部在线、Enter/A–Z 确认键均保留。
- 非密码服务信息保存在只允许 SYSTEM/管理员修改的 `HKLM\SOFTWARE\BluetoothUnlockApp`；密码仍保存在原有受限密钥，不交给监听服务。
- 用户确认的设置保存在 `<账户 SID>` 目录（仅绑定用户、管理员、SYSTEM 可修改）；服务快照与日志在同级 `<账户 SID>-runtime` 目录（绑定用户只读）。会话自动锁定日志写入配置目录 `session-events.log`，界面合并展示两份日志。在线状态不跨启动沿用。
- 无服务的开发/旧安装方式仍可使用 `--run`；服务启用后 `--run` 转为会话后台，避免同时开两个监听器。停用服务可在管理员终端执行 `Stop-Service BluetoothUnlockService`，恢复执行 `Start-Service BluetoothUnlockService`。完整卸载还会删除会话任务，并将当前共享配置复制回本用户 LocalAppData，保留数据。
- 本机已验证自动启动服务配置、SYSTEM BLE 监听、登录组件管道读取、未绑定账户拒绝，以及停止服务后拒绝靠近登录。重启后的首次登录、真实按键提交及长期运行仍须实机验收；程序不会自行重启电脑。
